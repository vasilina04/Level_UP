# LEVEL UP · Универ

Конкурсный прототип цифрового деканата. Все учётные записи и учебные сведения вымышлены.

## Локальный запуск

В этой рабочей папке на Windows после подготовки базы и зависимостей можно открыть PowerShell в VS Code и выполнить `.\start-local.cmd`. Скрипт запускает Next.js через Node.js. Если порт 3000 уже занят, используйте `.\start-local.cmd --port 3010` и откройте [страницу входа на порту 3010](http://127.0.0.1:3010/login).

Нужны Node.js 24, pnpm 11 и PostgreSQL 15 или новее. Создайте отдельную базу `levelup` и пользователя с правом создавать таблицы в ней. Скопируйте `.env.example` в `.env`, укажите строку подключения и сгенерируйте значение `AUTH_SECRET`:

```sh
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64'))"
```

Для загрузки вымышленных данных задайте `ENABLE_DEMO_SEED=1`. Если нужно воспроизвести календарь с определённой датой, задайте `DEMO_DATE=2026-11-13` перед первым запуском seed. По умолчанию занятия привязаны к текущей неделе во Владивостоке. Seed повторно использует идентификаторы и сохраняет существующие заявки, настройки и квесты.

```sh
pnpm install --frozen-lockfile
pnpm db:generate
pnpm db:deploy
pnpm db:seed
pnpm dev --hostname 127.0.0.1
```

Откройте [кабинет](http://127.0.0.1:3000/login).

### Сценарии демонстрации

1. Войдите как студент. Откройте главную, карту семестра и любой этап. Прогресс рассчитывается по подтверждённым контрольным точкам.
2. Завершите личный квест «Повторить SQL-запросы». Если дедлайн ещё впереди, баланс увеличится на 30 XP. У академического квеста «Сдать лабораторную № 3» доступно ожидание подтверждения.
3. Создайте заявку. Её можно сохранить как черновик и отправить после проверки.
4. В другом браузерном контексте войдите как сотрудник, откройте заявку и переведите её на рассмотрение. В студенческом кабинете появятся статус, запись в истории и уведомление.
5. На странице «Учебные данные» сотрудник может подтвердить контрольную точку, перенести или отменить занятие, сменить аудиторию или преподавателя. Подтверждение обновит карту и квест. Изменение расписания создаст запись в истории и уведомление группы.
6. В кабинете Алексея откройте «Карта семестра» → «Курсовые» → «Сдать лабораторную № 3». Отправьте вопрос. Войдите как `teacher1`, откройте «Вопросы студентов» и ответьте. Уведомление в студенческом кабинете ведёт к переписке.

## Архитектура

| Страница | Сценарий |
| --- | --- |
| `/login` | Вход с ограничением частоты, сессия Auth.js |
| `/dashboard` | Следующие занятия, квесты, успеваемость, XP и достижения |
| `/semester-map`, `/semester-map/[position]` | Маршрут и контрольные точки каждого этапа |
| `/quests`, `/quests/[id]` | Фильтры, сроки, завершение и история |
| `/achievements` | Полученные награды и условия открытия |
| `/schedule` | День, неделя и история изменений |
| `/grades` | Работы, оценки, график динамики и сессия |
| `/documents`, `/documents/new`, `/documents/[id]` | Черновик, отправка и история статусов |
| `/notifications`, `/profile` | Центр уведомлений, тема и настройки |
| `/staff`, `/staff/[id]`, `/staff/academic` | Обработка заявок, контрольные точки, изменение аудитории |
| `/checkpoints/[id]`, `/teacher` | Условия задания, вопросы и ответы по дисциплине |

График успеваемости показывает среднее за неделю с учётом весов работ. Прогресс контрольных точек считается как доля выполненного веса. Существующие записи получают вес 1 при миграции. Seed задаёт разные веса и условия в демонстрационном семестре.

Next.js App Router рендерит приватные страницы по серверной сессии. Prisma хранит учебные записи, XP, уведомления и документы в PostgreSQL. Каждая операция использует идентификатор текущего пользователя из сессии и проверяет владельца или роль на сервере. Изменяющие формы проверяют Origin и проходят проверку Next.js Server Actions. Сессия использует HttpOnly и SameSite cookies, а по HTTPS в production также Secure. См. [Next.js Data Security](https://nextjs.org/docs/app/guides/data-security) и [Auth.js Credentials](https://authjs.dev/getting-started/authentication/credentials).

XP начисляется транзакционно из событий с уникальным ключом. Личный квест в срок приносит 30 XP, подтверждённая лабораторная 70, зачёт 200, этап 150, семестр 500. Порог следующего уровня составляет 200 × текущий уровень. Статус заявки, история, аудит и уведомление обновляются в одной транзакции.

UI использует Tailwind CSS, кнопку на основе shadcn/ui, Lucide, Inter, Recharts и Motion. Настройка анимаций учитывает системный режим уменьшенного движения.

## Проверки

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Сквозные тесты требуют отдельной базы с seed. Они изменяют её данные. На Windows можно указать путь к уже установленному Chrome через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Переменная `PLAYWRIGHT_BASE_URL` позволяет проверить уже запущенный экземпляр с той же тестовой базой. Проверки адаптивности используют 360, 375, 390, 768, 1024 и 1440 px.

## Развёртывание на Node.js

1. Подготовьте PostgreSQL и production-секреты. Задайте `DATABASE_URL`, `AUTH_SECRET` и `AUTH_URL=https://ваш-домен`. Сохраните `AUTH_LOCAL_HTTP=0`. Храните переменные в менеджере секретов или файле вне репозитория.
2. Выполните `pnpm install --frozen-lockfile`, `pnpm db:generate`, `pnpm db:deploy`, `pnpm build` и запустите `pnpm start --hostname 127.0.0.1` под менеджером процессов.
3. Настройте HTTPS на обратном прокси и передавайте корректные `Host`, `X-Forwarded-Host` и `X-Forwarded-Proto`. Включайте `TRUST_PROXY_IP=1` только если приложение закрыто от прямого доступа и прокси заменяет `X-Real-IP` адресом клиента.
4. Если нужен стенд жюри, включите `ENABLE_DEMO_SEED=1` при запуске seed. Для стенда с известными паролями ограничьте доступ на уровне прокси.
5. После установки DNS и сертификата проверьте вход по HTTPS и доступность с целевой сети в России. Географическая доступность зависит от выбранного хостинга и маршрутизации.

Для Compose задайте `POSTGRES_PASSWORD` и `DATABASE_URL=postgresql://levelup:<пароль>@db:5432/levelup?schema=public`. Спецсимволы пароля в URL кодируются. Затем выполните `docker compose up -d --build`. При локальном запуске Compose используйте `AUTH_URL=http://localhost:3000` и `AUTH_LOCAL_HTTP=1`. Загрузите вымышленные данные командой `docker compose exec -e ENABLE_DEMO_SEED=1 app pnpm db:seed`. Порт приложения привязан к loopback для использования через локальный прокси.

### Резервные копии

Создавайте копии с учётными данными из защищённого окружения. Сохраняйте их вне проекта и регулярно проверяйте восстановление в отдельную базу.

```sh
pg_dump --format=custom --file=levelup.dump --dbname="$PG_BACKUP_URL"
pg_restore --exit-on-error --no-owner --dbname="$PG_RESTORE_URL" levelup.dump
```

Используйте строку подключения для PostgreSQL без параметра Prisma `schema`. Для периодического удаления истёкших записей ограничения входа выполните `DELETE FROM "LoginAttempt" WHERE "expiresAt" < now()` от отдельной служебной роли.

## Границы прототипа

- Прототип содержит один демонстрационный семестр. Календарь и задания привязаны к дате первой загрузки данных.
- Оценки и экзамены загружаются из демонстрационных учебных данных.
- Готовность заявки обозначает статус обработки. Выбранный способ получения и контактные данные сохраняются в заявке. Фактическая отправка по электронной почте, почтовая доставка и выпуск подписанных справок требуют интеграции с вузом.
- Уведомления доступны внутри кабинета. Напоминания создаются при обращении к приложению.
- Публичное развёртывание, доставка справок и проверка доступности из России требуют выбранного сервера.
